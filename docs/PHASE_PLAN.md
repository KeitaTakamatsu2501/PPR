# PPR フェーズ計画

策定：2026-09-15。Phase 0 完了時点。

本書が進め方の正となる。`EXECUTION_PLAN.md` / `IMPLEMENTATION_PLAN.md` / `ACCEPTANCE.md` / `IMPLEMENTATION_HANDOFF.md` は、仕様の詳細と経緯の資料として残す。両者が食い違う場合は本書と `PHASE_0_FINDINGS.md` を優先する。

## 1. 目的

一度作った人格を、作った作品の中だけで終わらせず、別のプロジェクトへ流用できる形にして、資産として育てる。

## 2. 三層

| 層 | 責務 | 置き場所 |
|---|---|---|
| 人格設定 | 価値観、判断、感情、口調。作品に依存しない | PPR（資産） |
| 作品ごとの構成作家 | JTSなら会話の流れ、SBTなら投稿と応酬。その作品で人格をどう登場させるか | 各作品 |
| 接続部分 | 作品側の状況と要求を生成処理へ渡し、結果を各作品の形式へ戻す | PPRが契約を定義、各作品が実装 |

Phase 0 で、JTS側にこの三層の継ぎ目が既に存在することを実測で確認した。詳細は `PHASE_0_FINDINGS.md`。

## 3. 確定した方針

- 資産化の対象は8人。ミラ、ヴェルミリア、宙星リリカ、ラティア、久本礼司、テルミナス、リュシエラ、イオネ。
- ヒロアキは意図的に人格を薄くしたJTS特化の設定のため対象外。JTS側では現役のまま残す。
- 研究用に作られた残り20人は移植も有効化も予定しない。
- locale は ja-JP のみを対象とする。海外対応は準備中のため、データモデルには locale 構造を残し、検証は ja-JP に限る。
- JTSへの書き戻しは判断保留。二重管理を許容する。JTSは10月サービス開始に向けて動いており、人格と役割が分離できていないため、PPRの成果物を組み込むリスクを取らない。
- 最終的にJTSがPPRの管理する人格から独立したままでも構わない。
- JTSのソースは変更しない。Phase 0 で、キャラクターJSONがP6Eリリースの資産契約（マニフェストのホワイトリスト、bind mount、systemdのマウント依存、キャラクター厳密2体の検査）に組み込まれていることを確認済み。PPR形式リーダーの追加はアプリ層ではなくデプロイ経路の変更になる。
- 人格本文は自動改稿しない。作品の都合で原文を書き換えない。
- 人格の同一性を数値で証明することは目標にしない。

## 4. フェーズ

### Phase 0 — 接続契約の実地調査（完了：2026-09-15）

JTSの高品質オフライン生成を、JTS無変更のままPPR側から実行し、構成作家が人格へ何を要求するかを実測した。結果は `PHASE_0_FINDINGS.md`。

得られた結論：人格を構成作家へ渡すのに必要な情報は原典の12〜27%。圧縮は原文断片の抽出で行われ、LLM要約は使われていない。

### Phase 1 — 人格をPPR形式で取り出す（完了：2026-09-15）

8人 / ja-JP。取込は一方向（読み取りのみ）。書き出しとJTS反映は作らない。

- PPRネイティブの人格形式を確定する。Phase 0 の実測フィールドを満たすこと。
- 独立起動と編集GUI。音声必須の除去。
- 4本文は `【...】` 見出しで階層化された構造化文書である。単一テキストエリアでは実用に耐えない。
- 21件（研究用20＋ヒロアキ）は取込原本のbytesとして保持するが、編集対象にはしない。

完了条件：JTSが参照不能な環境で、8人を開いて編集・保存・再読込できる。

達成。詳細は [IMPLEMENTATION_STATUS.md](IMPLEMENTATION_STATUS.md)。

### Phase 2 — 三層の関節を通す

`build_persona_context` を固定し、2作品で実証する。

- JTS会話（Phase 0 のハーネスを発展させる。実運用の構成作家を相手にできる）
- SBTスレッド（新規）

同じ人格revisionが、scheme側のキャラID分岐なしで両方へ通ることを確認する。呼称契約を層3の必須部品として実装する。コンテキスト不足時の縮約は、原文断片の抽出で行う。作者選択とモデル選択のどちらを既定にするかはここで決める。

完了条件：同一revisionで2作品の試演が通り、ライブラリが変更されない。

### Phase 3 — JTSへの反映（無期限保留）

判断を保留したまま凍結する。必要になった時点で `service_run_resolver` のDI注入点から入る。

### Phase 4 — ワークショップと多言語

設定ワークショップは Phase 2 で層の切り分けが確定してから作る。海外locale は準備状況に合わせる。

## 6. 二重管理の扱い

8人の人格はJTS側とPPR側で分岐していく。放置すれば同じ名前の別人になる。

- 取込時に元ファイルのSHA-256と取込日時を記録し、「取込後にJTS側が変わったか」をいつでも表示できるようにする。
- 基準日を決める。その日以降はPPR側が人格の正本とし、JTS側はJTSの都合でのみ変更する。JTSの10月ローンチ後が区切りの候補。

## 7. Phase 0 後の決定（2026-09-15）

### 7.1 モード別扱いの適用範囲

「恒常的な価値境界」の `【モード別扱い】` は、議論（attack）、意見交換（object_and_expose_bias）、解説、相談の4モードを持つ。

- **ベースは議論と意見交換**とする。試演の既定もこの2つ。
- **相談モードは適用しない。** 相談は人格よりも相談者へ寄り添うよう設計されており、人格の表出を測る用途に合わない。
- 原文は改稿しない。4モードすべてを原文のまま保持し、適用範囲は層3（接続部）が決める。
- 作品非依存の部分（忌避価値、保護対象、反射的反論、同意境界）とJTS固有の部分を構造的に分離するかは、Phase 2 の結果を見て判断する。

### 7.2 コンテキスト不足時の縮約

**モデル選択を既定とする。** JTSのAdaptive経路と同じ方式。小カテゴリの名前一覧をモデルへ提示し、モデルが関連カテゴリを選び、選択分の原文だけを投入する。

縮約は常に原文断片の抽出で行い、LLMによる要約は使わない。作者による明示選択は将来の選択肢として残すが、既定にはしない。

### 7.3 二重管理の基準日

**未定。JTSの10月ローンチ後であることは確定。** 具体的な日付は後日決める。
